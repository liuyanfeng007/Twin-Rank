# Twin-Rank 项目总结

## 一句话
面向电商场景的**两阶段推荐系统**：双塔向量召回 + 可切换精排（LightGBM / DeepFM / DCN / DIN）+ MMR 重排，配套 MLflow 模型注册（质量门禁）、FastAPI 在线服务与 Web 演示。

## 技术栈
PyTorch · Faiss · LightGBM · MLflow（Tracking / Model Registry / pyfunc）· FastAPI · Redis · Reflex · pandas / numpy / scipy

## 项目亮点
1. **完整闭环**：数据 → 训练 → 索引 → 精排 → 重排 → 注册 → 服务 → 演示，不只是单个模型。
2. **防泄露的评估设计**：按时间 leave-last-out；编码器与热度仅用训练集；精排样本取自验证集用户；指标与模型文件用指纹绑定。
3. **可插拔精排**：统一接口下四种模型一行配置切换，可在同一份候选上公平对比。
4. **训练-服务一致**：离线造样本与在线打分共用同一份特征代码。
5. **MLOps 实践**：整套系统打包成单个 pyfunc 模型；**质量门禁**保证"最新 ≠ 最好"；champion / challenger / previous 别名支持灰度与一键回滚。
6. **工程细节**：跨平台（macOS / Linux / Windows），环境自检，GPU 不兼容自动回退，自定义数据列映射接入。

## 示例结果（请替换为你自己最新一次的数据）

下面是 Video_Games 类目、LightGBM 精排、测试用户约 1 万的一次运行（样本规模较小的调试配置，仅作示例）：

| 方案 | Recall@10 | NDCG@10 | Recall@50 |
|---|---|---|---|
| 仅召回 | 0.0479 | 0.0259 | 0.1265 |
| 召回 + 精排 | 0.0564 | 0.0297 | 0.1433 |
| 召回 + 精排 + 重排 | 0.0515 | 0.0279 | 0.1177 |

候选命中率 `candidate_hit_rate` = 0.1877（精排的效果上限）。精排相对仅召回，Recall@10 提升约 18%；加上重排后指标回落是用相关性换多样性的预期结果。
**写简历 / 汇报前**请用 `make pipeline`（或 `make compare-rankers`）在完整样本量下重新跑一遍，使用 MLflow 里最新的 `test_*` 指标。

* 抽象统一精排接口，支持 **LightGBM / DeepFM / DCN-V2 / DIN** 配置切换，在同一候选集上对比，NDCG@10 最优为 **__**（模型：**__**）。
* 搭建 **MLflow 模型注册与质量门禁**：整套系统打包为 pyfunc 模型，新版本指标超过 champion 才晋升，支持灰度与一键回滚。

## 3 分钟演示脚本
1. 打开 Demo，选一个用户，展示他的**最近行为**。
2. 看左右两列：**左边仅召回，右边精排+重排**；指出位次变化（如 召回 #12 → 最终 #1 ▲11）和**推荐理由**。
3. 点击右侧一个商品（模拟反馈），推荐列表实时刷新。
4. 切到 MLflow：展示 `make compare-rankers` 的四个 run、`models` 页面的 champion / challenger 版本与指标标签。
5. 一句话收尾：新模型指标没超过 champion 时**不会上线**，需要时 `--rollback` 一键回滚。

## 常见追问与回答要点
| 问题 | 要点 |
|---|---|
| 为什么要召回 + 精排两阶段？ | 商品太多无法全量精排；召回求"全"、速度快，精排求"准"、可用复杂特征 |
| 双塔为什么能快？ | 物品向量离线算好建索引，线上只算一次用户向量 + 一次近邻检索 |
| 为什么需要 logQ 修正？ | batch 内负采样时热门商品更容易当负样本，会被过度打压，减去 log 采样概率抵消 |
| 怎么避免数据泄露？ | 按时间切分、编码器与热度仅用训练集、精排样本来自验证集用户、历史只含该时刻之前的行为 |
| 精排为什么不一定比召回好？ | 精排只能在候选里排序（命中率是上限）；样本少时易过拟合；用 `candidate_hit_rate` 与分组指标定位 |
| 为什么重排会降低离线指标？ | MMR 用相关性换多样性；离线只衡量命中，不衡量多样性与长期体验，需 A/B 验证 |
| 离线指标好就能上线吗？ | 不能。需要曝光日志、A/B 测试；本项目的门禁只是上线前的第一道关 |
| 项目最大的局限？ | 只有隐式正反馈、没有曝光负样本；用户塔较简单；没有新商品冷启动（见 ARCHITECTURE 第 6 节） |
